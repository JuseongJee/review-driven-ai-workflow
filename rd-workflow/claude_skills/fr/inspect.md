## /fr inspect

단일 FR 하나를 심층 검토하여 요약 보고하고, 그 FR 을 autopilot 으로 자율 실행할 수 있는지까지 판정합니다. **읽기 전용 — 파일 수정 없음.**

### 호출 형식

`/fr inspect <short-title>`

### 절차

1. **인자 검증**: `<short-title>` 이 없으면 `사용법: /fr inspect <short-title>` 출력 후 종료. 인자는 short-title 전용입니다. 사용자가 "15번"처럼 번호로 말한 경우, 번호→short-title 변환은 자연어 라우팅 단계(SKILL.md)에서 직전 `/fr list` 출력 기준으로 이뤄지며, inspect 절차 자체는 번호를 받지 않습니다 (list 번호는 정렬·필터로 매번 바뀌는 휘발성 값입니다).
2. **항목 탐색** (인덱스 기반):
   - `rd-workflow-workspace/backlog/FUTURE_REQUESTS.md` 활성 인덱스에 있으면 → 검토 진행.
   - 활성에 없고 `rd-workflow-workspace/backlog/FUTURE_REQUESTS_PARKED.md` 인덱스에 있으면 → parked 상태를 보고서에 명시하고 검토 진행.
   - 두 인덱스 어디에도 없으면 → `'<short-title>' 은 활성/parked 목록에 없습니다 (done/dropped 로 종료되었거나 오타일 수 있습니다)` 안내 후 종료. done/dropped 등 종료된 항목은 inspect 대상이 아닙니다 (inspect 는 "진행할까" 판단 도구이므로). 날짜 미상 glob 탐색은 도입하지 않습니다.
3. **최소 입력 범위 read** (이 범위 이상은 판단에 따라 확장 가능):
   - (a) 대상 FR 상세 파일 (`items/*.md`)
   - (b) 활성 상태 확인용 `FUTURE_REQUESTS.md` 인덱스 (+ 필요 시 PARKED)
   - (c) `rd-workflow/claude_skills/fr/SKILL.md` 및 관련 기존 절차 파일
   - (d) `rd-workflow/claude_skills/autopilot/SKILL.md` 의 **autopilot 적합성 기준** 섹션
   - (e) 대상 FR `related files` 중 직접 영향 파일
4. **related files 실재 확인**: `bash rd-workflow/scripts/check_fr_related_files_existence.sh <대상 FR items 경로>`를 호출합니다. 출력이 `대상 N개 중 M개 부재`(M>0)면 5번 「범위 폐쇄성」 판정에 부정적 신호로 반영하고 비율을 5번 표에 적습니다(M=N이면 강한 신호, 0<M<N이면 범위 재검토 신호). `대상 N개 중 0개 부재`(M=0)면 긍정적 신호로 반영하고, 검사가 실제로 돌았다는 근거로 이 비율을 그대로 5번에도 적습니다. `검사 대상 없음`이면 원인을 단정하지 않습니다 — "related files 자체가 비어 있습니다"라고 쓰지 말고 "검사 가능한 경로가 추출되지 않아 이 검사로는 판단할 수 없습니다"를 4번(미결·위험·질문)에 남깁니다(값이 있는데 제외 토큰뿐인 경우까지 "비어 있음"으로 잘못 안내하지 않기 위함). `exit 2`(스크립트 실행 오류)면 판정 불가로 4번에 명시하고 5번 「범위 폐쇄성」 충족 근거로 쓰지 않습니다.
4-1. **등록 뒤 변경 이력 확인**: `bash rd-workflow/scripts/fr_related_history.sh <대상 FR items 경로>`를 호출합니다. 이 FR 이 등록된 뒤 related files 를 바꾼 커밋 수와 최근 커밋을 보여 주는 참고 신호입니다. 첫 줄에 따라 이렇게 씁니다.
   - `변경 N건`(N>0): 나열된 커밋이 이 FR 의 문제를 이미 해결했는지 확인하고, 그 판단을 3번(검토 결과)에 적습니다. 같은 파일의 무관한 수정도 세므로 건수만으로 판단하지 않습니다.
   - `변경 0건`: 등록 뒤 관련 파일이 바뀌지 않았다는 근거로만 3번에 씁니다.
   - `검사 대상 없음`·`판정 불가(사유)`·`exit 2`: 4번(미결·위험·질문)에 그대로 적고, 해결 여부의 근거로 쓰지 않습니다.
   - 이 신호만으로 FR 을 종결하거나 상태를 바꾸지 않습니다. 판정은 사람이 합니다.
5. **검토 수행**: 본질과 객관 규칙 기준으로 타당성·범위·근본성을 비판적으로 검토합니다 (진짜 root cause 인가, 본말전도 없는가, 범위가 닫혀 있는가).
6. **autopilot 판정**: autopilot SKILL.md 의 **autopilot 적합성 기준** 섹션을 적용해 가능 / 조건부 가능 / 불가 를 판정합니다. 별도 판정 로직을 만들지 않고 그 섹션을 인용합니다.
7. **고정 섹션 보고서 출력** (아래). 어떤 파일도 수정하지 않습니다.

### 출력 — 고정 섹션 보고서

자유 형식 요약이 아니라 아래 6개 섹션을 **이 순서대로** 모두 채웁니다 (해당 없으면 "없음" 명시).
6번이 마지막이며, 터미널에서 사용자가 가장 먼저 보는 자리입니다.

1. **대상 FR 식별** (권장: 표 5행) — 제목 / 상태 / 종류 / 우선순위 / 상세 경로.
2. **읽은 근거 파일** (권장: 불릿 8개 내외) — 실제로 읽은 파일 목록.
3. **검토 결과** (권장: 5줄 내외) — 타당성·범위·근본성 비판 검토 결과.
4. **미결·위험·질문** (권장: 5항 내외) — 빠진 정보, 위험, 사람이 답해야 할 질문.
5. **autopilot 판정 근거** (권장: 판정표 + 조건 3줄) — autopilot SKILL.md 적합성 기준
   4항목별 판정과 근거. 조건부면 충족 조건과 사람 결정 필요 여부를 분리합니다.
   불가면 차단 사유를 적습니다.
6. **한눈에 보는 요약** (12줄 이내) — 아래 5요소를 이 순서로 씁니다.
   - **무엇을 하는 작업인가요.**
   - **좋은 점.**
   - **조심할 점.**
   - **여파는 어디까지인가요.**
   - **결론.** 마지막에 autopilot 판정 결과를 한 줄로 덧붙입니다.

1~5번은 표 또는 불릿으로 간결하게 씁니다. 괄호 안 권장 분량은 목표치이며 상한이 아닙니다 —
필요하면 넘겨도 됩니다. 6번의 12줄은 상한입니다.

#### 6번 요약 작성 규칙

- 완결된 문장으로 씁니다. 명사형 나열과 표를 쓰지 않습니다.
- 다음 표현을 쓰지 않습니다: `seed`, `AC`, `promote`, `drift`, `parity`, `canonical`,
  `폐쇄성`, `비가역`, `산출물`, `게이트`. 뜻이 필요하면 풀어서 설명합니다.
- 1~5번에 쓴 내용을 옮길 때도 내부 용어를 그대로 가져오지 않고 다시 풀어 씁니다.

✗ `seed 구체성 미흡 — AC 보강 필요`
✓ `착수 전에 '어느 수준까지 만족하면 끝인가'를 숫자로 적어 두면 됩니다.`

### 규칙

- **읽기 전용**: FR 파일·인덱스·산출물을 절대 수정하지 않습니다. 상태 변경은 `/fr status`, 우선순위 기록은 `/fr pri`, 실제 실행은 `autopilot` 의 책임입니다.
- autopilot 판정은 autopilot SKILL.md 의 적합성 기준을 단일 출처로 인용하며 기준을 여기에 복제하지 않습니다.
- 단일 항목 전용입니다. 여러 항목 일괄 검토는 하지 않습니다 (전체 우선순위는 `/fr pri`).
- 6번 요약은 생략하거나 다른 섹션과 합치지 않습니다. 보고서의 마지막 출력이어야 합니다.
- 6번의 금지 표현 목록은 요약 섹션에만 적용됩니다. 1~5번은 기존대로 정확한 용어를 씁니다.
