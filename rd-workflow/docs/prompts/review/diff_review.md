최신 변경 diff를 리뷰해줘.

검토 기준
- 논리 버그
- 회귀 위험
- 성능 문제
- 보안 문제
- 치명 결함 범주 — diff 밖 호출부·소비처까지 읽고 확인한다
  - 데이터 안전: 삭제·덮어쓰기·부분 실패 뒤 데이터가 손실되거나 어긋나는 경로가 있는가
  - 경쟁 조건: 동시 실행·재실행·중단 후 재개에서 상태가 깨지는가
  - 신뢰 경계: 외부 입력·LLM 출력·파일 내용이 검증 없이 명령·경로·쿼리(셸 인젝션 포함)로 들어가는가
  - 열거형 완전성: 새 값·상태를 모든 소비처가 처리하는가
- 유지보수성 저하
- 불필요한 복잡성
- CLAUDE.md 비대화: 변경이 CLAUDE.md를 수정했다면 "이 문장을 삭제해도 실수가 발생하는가?" 원칙을 적용. `.claude/rules/` 합계도 12000자 이하 유지 권장 (`check_claudemd_size.sh` 기준)
- CURRENT_TASK.md 정합: 커밋된 `CURRENT_TASK.md`가 HEAD 기준 현재 단계(Status·Spec·Plan·Next Step)와 일치하는가
- 변이 증거: 이 변경이 새로 만들거나 바꾼 필수 대상 단언(부정 명제·회귀)의 결과표가 최신 Author 턴 기준으로 현재 diff 와 맞고, `검증됨` 행이 유효 증거 4조건을 지키는가. 결과표가 없거나, `검증됨` 행이 4조건을 어기거나, `생존`·원복 `미확인` 행이 있으면 이의. `무효(사유)` 행의 사유가 가이드의 닫힌 목록 밖이거나 실제로 성립하지 않으면 이의(그 행은 `생존` 일 수 있다). 필수 대상의 마지막 행이 `무효(사유)` 이면 이의. 결과표 머리말이나 행의 기준이 실제 SHA 가 아니어서 기준을 복원할 수 없으면 이의. `미검증(사유)` 는 사유와 잔여 위험을 보고 수용 여부를 적는다(수용해도 검증 성공으로 세지 않는다). 직접 주입은 선택이며 작업 트리 밖 사본에서만 한다 (`rd-workflow/docs/guides/mutation-check.md`)
- spec·plan·AC 이탈: diff 가 spec·plan(`full`) 또는 REQUEST AC(`standard`)와 어긋나는가. 경로는 `CURRENT_TASK.md` 의 `## Spec`·`## Plan` 에서 찾는다. 사유가 spec 의 「구현 중 변경」 절이나 REQUEST 에 없으면 이의
- 범위 밖 변경: REQUEST·CURRENT_TASK 에 적힌 범위를 벗어난 리팩터링·포맷·파일이 있는가 (spec·AC 에 없는 변경)
- 테스트 거짓말: 새·변경 테스트가 동어반복·구조 결합·mock 과다 중 하나면 이의 (정의: `.claude/rules/rd-workflow/core.md` 테스트 규칙)
- macOS 기본 도구: 새·변경 셸 테스트는 그 파일만 `PATH=/usr/bin:/bin:/usr/sbin:/sbin bash <파일>` 로 한 번 실행한다(이 PATH 는 BSD `sed`·bash 3.2 다). 개발 머신의 GNU 도구에서만 통과하면 이의. 실행할 수 없는 환경이면 Summary 에 미실행이라고 적는다
- 주석: 새·변경 주석이 리뷰 턴·지적 번호 같은 출처를 달거나 일회성 피드백을 규칙처럼 적으면 이의. 주석에는 '왜' 만 남긴다
- 제거 신호: 이 변경(요청·설계·규칙)으로 쓰이지 않게 된 코드·분기·설정·문서 절, 같은 사실을 두 곳에 둔 규칙, 발동한 적 없는 만약을 위한 처리, 반복해서 지켜지지 않는 규칙(문구 강화 대신 검사·hook 으로 바꾸거나 삭제)이 있는가. 있으면 `제거:` 발견으로 낸다
- 정리 후보: diff 가 닿은 파일에서 이번 변경과 무관하게 이미 있던 로직 중복·크기 기준(프로젝트 규칙)을 넘은 파일·남겨 둔 임시 코드나 우회를 보면 Findings 가 아니라 Summary 끝에 `정리 후보: <경로> — <내용>` 줄로 적는다. 이의가 아니므로 종결을 막지 않는다. 이번 변경이 만든 것은 `제거:` 발견으로 낸다
