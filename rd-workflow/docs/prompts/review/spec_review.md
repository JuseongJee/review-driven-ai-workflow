rd-workflow-workspace/specs/와 rd-workflow-workspace/plans/의 최신 문서를 검토해줘.

검토 기준
- 과도한 설계 여부
- 빠진 엣지 케이스
- 더 단순한 대안
- 테스트 전략 누락
- 플랫폼별 리스크(web / macOS / iOS)
- 아키텍처 경계: 책임이 맞는 모듈에 놓였고 의존 방향이 뒤집히지 않았는가
- 데이터 흐름 엣지 케이스: 빈 입력·부재·중복·부분 실패·재실행에서 어떻게 동작하는가
- 테스트 매트릭스: AC 마다 그것을 확인하는 검증이 plan 에 있는가
- 사용자 가시성: 사용자가 이 변경의 결과·진행·실패를 볼 수 있는가
- 변이 명세: plan 이 테스트의 필수 대상 단언(부정 명제·회귀)을 새로 만들거나 바꾸면(기존 테스트에 단언을 더하는 경우 포함) 그 단언마다 FAIL 을 유발할 `변이:` 줄이 있는가. 누락되거나 그 변이로 단언이 실패하지 않을 것으로 보이면 이의 (`rd-workflow/docs/guides/mutation-check.md`)
- 제거 신호: 이 변경(요청·설계·규칙)으로 쓰이지 않게 된 코드·분기·설정·문서 절, 같은 사실을 두 곳에 둔 규칙, 발동한 적 없는 만약을 위한 처리, 반복해서 지켜지지 않는 규칙(문구 강화 대신 검사·hook 으로 바꾸거나 삭제)이 있는가. 있으면 `제거:` 발견으로 낸다
