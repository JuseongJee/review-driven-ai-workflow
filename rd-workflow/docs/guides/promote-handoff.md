# promote 인계 파일 형식

`promote.sh` 는 호출 세션이 사용자와 확정한 결정을 새 세션에 전달하는 통로로 `--handoff <file>` 인자를 제공합니다. 이 문서는 그 파일의 형식과 호출 방법을 정의합니다. 이 문서가 인계 형식의 정본입니다.

## 목적

호출 세션은 promote 전에 사용자와 결정을 확정합니다. promote 가 기동한 새 세션은 `CURRENT_TASK.md` 만 받으므로 그 결정을 모릅니다. 호출 세션은 promote 직후 멈춰야 하므로 기동 뒤에 결정을 보강할 수 없습니다. 인계 파일은 이 손실을 막습니다. promote 는 세션을 기동하기 전에 이 파일을 기록하고, 인계 문구는 새 세션에 이 파일을 먼저 읽도록 지시합니다.

## 형식

파일은 아래 4개 절을 이 이름 그대로, 이 순서로 씁니다. promote 는 절 존재를 검사하지 않습니다. 형식 위반은 사람 리뷰가 받습니다.

### `## 확정 결정`

사용자와 확정한 결정을 한 줄에 하나씩 적습니다. 각 결정에 근거를 붙입니다. 결정의 값(브랜치 이름, 등급, 범위)을 구체적으로 적고 "적절히" 같은 모호어를 쓰지 않습니다.

FR 없이 시작한 작업은 사용자 원문을 이 절의 첫 항목으로 그대로 적습니다.

### `## 받는 세션이 해도 되는 행동`

받는 세션이 수행할 수 있는 행동을 표로 적습니다. 열은 `행동 / 결정 내용 / 담당` 입니다.

| 행동 | 결정 내용 | 담당 |
|---|---|---|
| (예) 후속 FR 등록 | 제목, 요약, 범위, 미결정 사항을 모두 적습니다 | 받는 세션 |

작성 기준:

- 이번 작업의 구현 행동만 적지 않습니다. 후속 FR 등록처럼 받는 세션이 할 수 있는 다른 행동도 모두 적습니다.
- 각 행동에 그 행동에 필요한 결정을 모두 적습니다. 결정 한 문장으로 줄이지 않습니다.
- 담당을 적습니다. "받는 세션" 인지 "호출 세션" 인지 "사용자" 인지 명시합니다.

근거: 2026-10-26 mac-setup-sync 사례에서 호출 세션은 후속 FR 결정을 인계 파일에 한 문장으로만 적었고 담당을 적지 않았습니다. 받은 세션은 그 문장만으로 FR 을 등록했고 보존 목록 이동·마이그레이션·영향 검사·미결정 사항이 빠졌습니다. 인계 문구는 새 세션에 이 절 밖의 행동을 하지 말라고 지시하므로, 이 절에 없는 행동은 받는 세션이 수행하지 않습니다.

### `## 하지 않는 행동`

받는 세션이 하지 않아야 하는 행동을 적습니다. 사용자가 명시적으로 금지했거나 호출 세션이 맡기로 한 행동을 포함합니다.

### `## 미결정`

아직 정하지 않은 사안을 적습니다. 받는 세션이 임의로 정하지 않고 사용자에게 묻도록 하기 위함입니다. 없으면 "없음" 이라고 적습니다.

## 호출 방법

`--source-fr -` 이면 별도 결정 유무와 무관하게 파일을 쓰고 `--handoff` 로 넘기는 것이 필수입니다. FR 이 있을 때만 확정한 결정이 있을 때 파일을 쓰고 `--handoff` 로 넘기며, 결정이 없으면 인자를 생략합니다.

```bash
bash rd-workflow/scripts/lifecycle/promote.sh --short-title <slug> --size small \
  --source-fr <items 경로 또는 -> --handoff <file>
```

promote 의 동작:

- 입력을 검증합니다. 파일이 없거나, 디렉터리이거나, 읽을 수 없거나, 비어 있거나, 64KiB(65536 바이트)를 넘으면 브랜치·worktree 를 만들기 전에 `exit 1` 합니다.
- 세션 기동 전에 `<작업 디렉터리>/rd-workflow-workspace/.lifecycle/handoff.md` 에 복사하고 원본과 대조합니다. 성공하면 `promote: 인계 기록 — ok (<경로>)` 를 출력합니다.
- 이 파일은 `.gitignore` 로 추적에서 제외합니다. 런타임 인계 파일이므로 커밋하지 않습니다.
- `--handoff` 없이 새 작업 내용을 쓰는 호출은 같은 체크아웃에 남은 이전 작업의 `handoff.md` 를 지웁니다.
- 자동 기동이 없으면(`promote: 세션 기동 결과 — none`) promote 가 인계 파일 경로와 새 세션에 붙여 넣을 인계 문구를 출력합니다.
- 기록에 실패하면 색인과 기동을 건드리지 않고 `exit 1` 하며 복구 방법을 출력합니다.

## 재호출 보호

이미 진행 중인 작업에 같은 명령을 `--handoff` 와 함께 다시 호출하면 promote 는 살아 있는 worktree 에 인계 파일만 다시 기록합니다(`handoff_retry`). 브랜치·worktree·task-state 는 바꾸지 않습니다.

- 세션이 살아 있거나 미확정이면(`launch` 가 `launching`·`unknown`, 또는 `ok` 이고 세션이 살아 있거나 판정 불가) promote 는 파일을 바꾸지 않고 `exit 1` 합니다. 그 세션이 이미 파일을 읽고 있을 수 있기 때문입니다. 메시지가 사유와 `rd task resolve-launch <slug>` 안내를 담습니다.
- `launch` 가 `none`·`failed` 이거나 비어 있거나 세션이 죽었으면 파일을 교체하고 세션을 기동합니다.
- `--no-worktree` 는 이 재시도 경로를 제공하지 않습니다. 기록에 실패하면 promote 가 출력하는 `cp <원본> <대상>` 명령으로 직접 복사한 뒤 안내된 기동 명령을 실행합니다.
