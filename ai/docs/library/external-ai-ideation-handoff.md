# 외부 AI 아이데이션 핸드오프

이 문서는 별도 AI에서 초기 아이디어를 발산하되, 이 템플릿의 공식 흐름으로 자연스럽게 넘어오게 만드는 시작 프롬프트와 handoff 기준을 정리합니다.

## 핵심 원칙

- 외부 AI는 `발산 -> 후보 압축 -> handoff 정리`까지만 맡긴다
- 공식 산출물인 `REQUEST.md -> spec -> plan` 파일은 이 템플릿 안에서 만든다
- 구현 코드, 상세 아키텍처, 세부 작업 분해는 너무 일찍 만들지 않는다

## 언제 쓰나

- 아직 구현할지조차 확정되지 않은 아이디어를 넓게 탐색할 때
- 문제 정의와 사용자 가치를 먼저 잡아야 할 때
- 후보 방향을 1~2개로 줄인 뒤 이 템플릿으로 가져오고 싶을 때

## 언제 바로 이 플로우로 들어오나

- 이미 유력한 방향이 정해져 있고 `REQUEST.md`로 바로 정리할 수 있을 때
- 기존 코드베이스 제약과 영향 범위가 핵심이라 레포 맥락이 먼저 필요할 때
- spec / plan 수준의 구조화가 이미 필요한 단계일 때

## 시작 프롬프트

아래 프롬프트를 외부 AI에 먼저 던지고 대화를 시작합니다.

```text
너는 지금부터 "초기 아이디어 발산 파트너"다.

나는 이 대화에서 아이디어를 넓게 탐색한 뒤, 어느 정도 수렴하면 별도의 프로젝트 워크플로로 넘길 예정이다.
그 워크플로에서는 최종적으로 `REQUEST -> brainstorming/spec -> plan -> implementation` 순서로 진행합니다.

그래서 지금 단계의 목표는:
1. 아이디어를 발산합니다.
2. 후보들을 비교해 유력한 방향을 좁힙니다.
3. 충분히 수렴하면 그 워크플로로 넘길 수 있는 handoff 자료를 만듭니다.

중요 규칙:
- 지금은 구현 코드, 상세 아키텍처, 세부 작업 계획까지 내려가지 말 것
- 먼저 문제 정의와 사용자 가치부터 명확히 할 것
- 아이디어는 3~5개 정도로 발산하고, 각 아이디어의 장점/차별점/복잡도/리스크를 짧게 비교할 것
- 질문은 한 번에 1~3개만 할 것
- 대화 중 생기는 파생 아이디어는 본 작업과 분리해서 `후속 아이디어`로 따로 정리할 것
- 어느 정도 수렴했다고 판단되면 더 발산하지 말고 아래 handoff 형식으로 정리할 것
- 내가 `이제 넘기자`라고 하면 즉시 handoff 형식으로만 정리할 것

handoff 형식:
- 한 줄 문제 정의
- 해결하려는 사용자/상황
- 유력 후보 1~2개
- 현재 가장 추천하는 방향 1개와 이유
- 이번 작업 범위에 넣을 것
- 이번 작업 범위에서 뺄 것
- 핵심 제약/가정
- 주요 리스크/애매한 점
- 남아 있는 질문
- `REQUEST.md`로 옮기기 좋은 짧은 초안

처음 응답에서는:
- 내가 답하면 방향이 크게 갈릴 핵심 질문 2~3개를 먼저 해줘
- 필요하면 아이디어 방향을 나눌 탐색 축도 같이 제안해줘

현재 메모:
[여기에 지금 떠오른 생각을 자유롭게 적기]

프로젝트/도메인:
[제품 또는 문제 영역 한 줄]

알려진 제약:
[있으면 적고, 없으면 없음]
```

## 대화 운영 규칙

- 초반에는 빠르게 발산하되, 2~3라운드 안에 후보 압축으로 넘어간다
- 후보 비교 기준은 사용자 가치, 차별점, 구현 복잡도, 리스크 정도면 충분하다
- 레포를 봐야만 답할 수 있는 항목은 확정하지 말고 `가정`으로 표시한다
- 현재 범위를 벗어난 파생 아이디어는 `후속 아이디어`로 분리해 둔다
- 외부 AI가 spec, plan, task breakdown까지 과하게 내려가려 하면 다시 문제 정의와 범위 조정 쪽으로 올린다

## Handoff 준비 완료 기준

아래 조건이 대부분 채워지면 handoff 결과를 들고 이 템플릿으로 넘어온다.

- 문제 정의가 한 문장으로 정리된다
- 누구를 위한 아이디어인지 정해졌다
- 후보가 1~2개로 줄었다
- 이번 범위와 제외 범위가 보인다
- 핵심 제약, 가정, 리스크가 드러났다
- `REQUEST.md` 초안으로 옮길 수 있는 문장이 생겼다

중요한 기준은 "좋은 아이디어인가"보다 "이제 `REQUEST.md`로 구조화할 수 있는가"다.

## 이 템플릿으로 넘길 때

1. 외부 AI가 정리한 handoff 결과를 이 저장소로 가져온다
2. 그 내용을 바탕으로 `REQUEST.md`를 만들어 달라고 짧게 요청하거나 `ai/docs/prompts/examples/make_request.md`를 그대로 넣는다
3. 작업 성격에 따라 아래 흐름으로 이어갑니다
4. 큰 작업이면 `request-to-reviewed-plan skill`을 호출하거나 `ai/docs/prompts/examples/start_large_or_existing_change.md`를 넣는다
5. 작은 작업이면 `small-task-implement skill`을 호출하거나 `ai/docs/prompts/examples/implement_small_task.md`를 넣는다

## 빠른 판단 요약

- 아주 거친 발산만 필요하다: 외부 AI에서 시작
- 구현 후보가 보이기 시작한다: 이 템플릿으로 이동
- 코드베이스 제약이 이미 중요하다: 처음부터 이 템플릿 안에서 시작
